# EC220-OURFW v0.3 — CI build repo

Минимальный набор для реальной сборки кастомной прошивки **TP-Link EC220-G5 v2** (MT7620A, 8 MB SPI NOR) на базе Padavan-NG.

Это исходники + CI. Готовый `.bin` собирается в облаке — локально ничего собирать не нужно.

## Как собрать

1. Открыть вкладку **Actions** → workflow **Build EC220 OURFW** → **Run workflow** (branch `main`).
2. Ждать окончания (примерно 1–2 часа).
3. Скачать артефакт **EC220-G5-v2-OURFW-v0.3**, внутри:

   - `TL_EC220_G5-V2_OURFW-v0.3-<commit>.bin` — web-образ для штатного обновления;
   - `tp_recovery.bin` — для первой заливки через TFTP recovery (128 KiB нулей + web-образ);
   - `BUILD-REPORT.txt`, `SHA256SUMS.txt`, `build.log`.

## Что делает CI

1. Статические проверки + mock-интеграция (без железа).
2. Клонирует **точный** commit Padavan `0e6caa2749a8814345c8a0d496a2fde2e6746a7d` (`hadzhioglu/padavan-ng`) — тот же, что в проверенном рабочем образе EC220.
3. Скачивает готовый toolchain, накатывает OURFW-интеграцию (патчер идемпотентный, fail-closed).
4. Собирает чистую сборку, проверяет размер против раздела Firmware `0x780000` (минус 64 KiB запас) и генерирует recovery-образ с побайтовой проверкой.

## Прошивка

Первая установка — только `tp_recovery.bin` через TFTP recovery роутера (ПК `192.168.0.66`, Reset + питание). Разметка flash не меняется. Stock Дом.ру ZIP держите отдельно как аварийный откат.

**Не прошивайте `.bin`, пока не сверили SHA256 из BUILD-REPORT.**

## Правки относительно исходного v0.3-пакета

- `ci/prepare-artifacts.sh`: ожидаемый размер раздела Firmware исправлен `0x7a0000` → `0x780000` (раньше CI всегда падал с exit 24);
- `ci/prepare-artifacts.sh`: образ выбирается по точному имени борды `TL_EC220_G5-V2_*.bin` вместо самого свежего по mtime;
- `tools/apply-to-padavan.py`: `make-defaults.sh` вызывается через `sh` (переносимость на Windows-хосты).
