# OURFW v0.7.1 — final hardware acceptance notes (2026-08-17)

> Notes-only branch. No v0.7.1 source implementation is made here.

## Final HWFIX1c acceptance result

Physical TP-Link EC220-G5 v2, base `v0.6.3`, overlay `v0.7.0-noflash-v063`.

Controlled backup failure test used a temporary OUTPUT chain dropping only UDP to `213.176.64.151:2096`.

Observed:

- temporary DROP rule matched exactly one Hysteria backup packet (`1 pkt / 1286 bytes`);
- `hy2-start-backup` returned `rc=1` with safe generic `detail=HY2_START_FAILED`;
- reconnect backoff activated immediately (`HY2_RECONNECT_COOLDOWN=14` shortly after failure);
- immediate primary retry was blocked locally with `rc=9` and `detail=HY2_RECONNECT_COOLDOWN=12`;
- after 17 seconds primary restored successfully (`RESTORE_RC=0`);
- successful connection reset cooldown to zero;
- Hysteria route remained off;
- test firewall chain was removed;
- policy routing remained clean (`local/main/default` only);
- table 101 was empty;
- `OURFW_HY2` chain was absent.

## Error-detail nuance still pending for v0.7.1

HWFIX1c added direct safe categories in `hy2-tproxy.sh`:

- `HY2_CONFIG_INVALID`
- `HY2_START_FAILED`
- `HY2_CONNECT_TIMEOUT`

However this controlled DROP test still returned `HY2_START_FAILED`, not `HY2_CONNECT_TIMEOUT`. This means the child exited through the startup-exit path before the wrapper's own 8-second timeout branch. The original defect (empty detail) is fixed, but the category is still coarse for this failure mode.

Do not spend more live-router testing time on this. For v0.7.1, improve classification in CI/unit tests and optionally classify known engine log patterns safely without ever exposing URI/auth/obfs secrets.

## Backoff verdict

Hardware-confirmed PASS:

- first network startup failure starts backoff;
- immediate retry is blocked without another network attempt;
- initial delay is approximately 15 seconds;
- successful later start resets cooldown;
- routing/firewall cleanup remains intact.
