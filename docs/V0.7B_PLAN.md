# v0.7b TPROXY / Hysteria2 plan

This branch is intentionally isolated from the v0.7a subscription-manager baseline.

## Goals

1. Prove the minimum Padavan kernel/netfilter delta required for TPROXY on EC220-G5 v2.
2. Build and size a minimal MIPSLE soft-float Hysteria2 client candidate.
3. Keep all network changes opt-in and rollback-safe.
4. Produce an on-router hotfix/update path for routers already running OURFW without requiring a full reflash when possible.

## Safety gates

- No automatic route, DNS, mangle, policy-routing, or kill-switch changes on boot.
- TPROXY capability probe remains read-only until explicit apply.
- Existing WireGuard/OpenVPN paths remain untouched.
- Existing v0.6.4/v0.7a hardware fixes must remain in ROMFS.
- Any hotfix package must be self-verifying and reversible.

## Integration order

1. [x] Kernel/module build proof.
2. [x] ROMFS/module presence verification.
3. [ ] Minimal Hysteria2 binary size/dependency proof.
4. [ ] Passive runtime self-test.
5. [ ] Controlled TPROXY data-plane test with rollback.
6. [ ] Hardware update package for an already-installed OURFW build.
